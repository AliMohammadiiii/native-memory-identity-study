# Bounded source intervention

This follow-up isolates one branch condition in the already inspected native
implementation. It does not make the earlier development data held-out, add
independent systems, or establish a new repair algorithm. The returned API
predecessor field and persisted graph are separate endpoints.

Before execution, run `run.py --plan-only` with a pinned native package directory,
the original benign capture and a fresh output path. Native execution requires
the same cached environment as the parent study, including sqlite-vec 0.1.6.
Run without `--plan-only` to freeze the exact instrument, parent bindings,
source arms and patches before any native call. No network is allowed during
worker imports or calls. Existing output directories are refused.

Use the analyzer frozen inside the capture for offline analysis:

```sh
python -B CAPTURE/intervention_instrument/analyze.py \
  --capture CAPTURE --out FRESH_ANALYSIS
```

All 24 cells must be present. Missing data, exceptions, changed bindings,
network attempts, sentinel loss and cold drift block interpretation. Raw
SQLite stores, intermediate observations, source variants and worker failures
are preserved. One source arm disables a native branch as a negative control;
it is not a proposed production repair. A guard can preserve current content
while leaving the response's self-valued predecessor field unchanged.

No paid/model/embedding requests, public disclosure, commits or submission are
part of this study. Counts are generated from captures and are never combined
with the earlier 32-cell unmodified denominator.
